## 4.1 类与对象：图纸和房子

玩 Minecraft 时，"钻石剑"这个**概念**是类；你背包里那一把**具体的、掉了 3 点耐久的钻石剑**是对象。

- **类（class）**：图纸。描述"这类东西有什么属性、能做什么事"。
- **对象（object）**：按图纸造出来的实物。一张图纸能造无数个实物。

```java
// 定义一个"剑"的类（图纸）
class Sword {
    // 属性（成员变量）：这类东西"有什么"
    String name;
    int damage;
    int durability;

    // 方法：这类东西"能做什么"
    void attack() {
        System.out.println(name + " 挥砍，造成 " + damage + " 点伤害！");
        durability--;   // 掉 1 点耐久
    }
}

public class Main {
    public static void main(String[] args) {
        // new = 按图纸造一个实物（创建对象）
        Sword diamondSword = new Sword();
        diamondSword.name = "钻石剑";
        diamondSword.damage = 7;
        diamondSword.durability = 1561;

        Sword ironSword = new Sword();
        ironSword.name = "铁剑";
        ironSword.damage = 6;

        diamondSword.attack();   // 钻石剑 挥砍，造成 7 点伤害！
        ironSword.attack();      // 铁剑 挥砍，造成 6 点伤害！
    }
}
```

- `new Sword()`：在内存中**创建**一个 Sword 对象（这个过程叫"实例化"）。
- `diamondSword` 和 `ironSword` 是两个**独立**的对象，各自有自己的 `damage`，互不影响。
- 用 `.`（点）访问对象的属性和方法：`对象.属性`、`对象.方法()`。

### 为什么前两课的方法都写 static？

`static` 方法属于类本身，不需要创建对象就能调用。而本课 `attack()` 是**普通方法**，必须先造出对象才能用——因为"挥砍"这个动作必须有一把**具体的剑**才能执行。

## 4.2 构造方法：造对象时的初始化

每次 `new Sword()` 后还要一行行设置属性，太麻烦。**构造方法**让你在 `new` 的同时完成初始化：

```java
class Sword {
    String name;
    int damage;

    // 构造方法：方法名必须和类名一模一样，且不写返回值类型
    Sword(String name, int damage) {
        this.name = name;      // this 指"当前这个对象自己"
        this.damage = damage;
    }

    void attack() {
        System.out.println(name + " 造成 " + damage + " 点伤害");
    }
}

// 创建时一步到位：
Sword sword = new Sword("下界合金剑", 8);
sword.attack();
```

> 💡 `this` 是什么？当参数名和属性名相同时（都叫 `name`），用 `this.name` 表示"对象的属性"，以区别于"传入的参数"。

> 💡 现在回看第 01 课的 `ExampleMod.java`：里面的 `public ExampleMod() { ... }` 就是构造方法——Forge 加载模组时 `new` 出你的模组对象，构造方法里的代码随之执行。

## 4.3 封装：把数据保护起来

直接暴露属性有风险，比如有人把耐久改成负数：

```java
class Sword {
    private int durability;   // private = 私有，类外部不能直接访问

    public void damage(int amount) {       // public = 公开的方法
        durability -= amount;
        if (durability < 0) {
            durability = 0;
        }
    }

    public int getDurability() {           // 提供受控的读取方式
        return durability;
    }
}
```

**封装**三原则：

1. 属性用 `private` 藏起来；
2. 提供 `public` 的方法（getter/setter 或业务方法）作为唯一入口；
3. 在方法里做合法性检查，保证数据不会被改坏。

## 4.4 继承：站在巨人的肩膀上

游戏里剑、斧、镐都有"名字、伤害、耐久"——如果每个类都抄一遍，重复又难维护。**继承**让子类自动拥有父类的一切：

```java
// 父类：工具（抽取公共部分）
class Tool {
    String name;
    int damage;

    Tool(String name, int damage) {
        this.name = name;
        this.damage = damage;
    }

    void showInfo() {
        System.out.println(name + "，攻击力 " + damage);
    }
}

// 子类：剑 继承自 工具（extends = 继承）
class Sword extends Tool {
    Sword(String name, int damage) {
        super(name, damage);   // super = 调用父类的构造方法
    }

    void sweep() {             // 剑独有的"横扫"技能
        System.out.println(name + " 使用了横扫攻击！");
    }
}

Sword s = new Sword("钻石剑", 7);
s.showInfo();   // 继承自 Tool 的方法，直接用
s.sweep();      // Sword 自己新增的方法
```

要点：

- `extends`：继承。子类自动拥有父类的所有非 private 属性和方法；
- `super(...)`：在子类构造方法里调用父类构造方法，且必须写在第一行；
- Java 中一个类只能有**一个**父类（单继承）。

> 💡 **在 Forge 里**：你写的方块类常常 `extends Block`，物品类 `extends Item`——你的方块立刻就拥有了 Forge 写好的所有基础行为，你只加自己的特色功能。这就是继承的实际用途。

### 方法重写（Override）：子类改造父类的方法

```java
class Tool {
    void showInfo() {
        System.out.println("这是一件工具");
    }
}

class Sword extends Tool {
    @Override                       // 注解：告诉编译器"我是故意覆盖父类方法的"
    void showInfo() {
        System.out.println("这是一把锋利的剑");
    }
}
```

`@Override` 不是必须的，但强烈建议写上——如果你不小心把方法名拼错，编译器会立刻报错提醒，而不是悄悄变成一个新方法。

## 4.5 接口（interface）：一份"能力合同"

接口只规定"**必须会做什么**"，不管"**怎么做**"。类通过 `implements`（实现）签下合同，就必须兑现合同里的每一条。

```java
// 接口：会飞的
interface Flyable {
    void fly();      // 接口里的方法只写签名，不写实现
}

class Bat implements Flyable {     // implements = 实现接口
    @Override
    public void fly() {
        System.out.println("蝙蝠扑棱翅膀飞");
    }
}

class Elytra implements Flyable {
    @Override
    public void fly() {
        System.out.println("鞘翅滑翔！");
    }
}
```

接口 vs 继承：

| | 继承（extends） | 接口（implements） |
|---|---|---|
| 数量限制 | 只能继承一个父类 | 可以实现**多个**接口 |
| 关系 | "是一种"（剑是一种工具） | "会一种能力"（蝙蝠会飞） |

```java
class Dragon extends Mob implements Flyable, FireBreathing { ... }
//       ↑ 继承一个父类        ↑ 同时实现多个接口
```

> 💡 **在 Forge 里**：实现接口非常常见。比如想让方块能存数据，就实现对应接口；想响应游戏事件，就实现监听接口。你在第 05 课就会用到。

## 4.6 static 与 final（快速了解）

- `static`：属于类而不属于对象。`static` 变量全类共享一份（如 `public static final String MODID = "examplemod"`——所有地方读到的都是同一个模组 ID）。
- `final`：最终的、不可变的。
  - `final` 变量：赋值后不能改（常量，通常全大写命名，如 `MODID`）；
  - `final` 类：不能被继承；
  - `final` 方法：不能被重写。

## 4.7 本课小结

- 类是图纸，对象是实物；`new` 创建对象，`.` 访问成员。
- 构造方法在创建对象时执行，用于初始化；`this` 指当前对象，`super` 指父类。
- 封装：属性 `private`，通过 `public` 方法受控访问。
- 继承 `extends`：复用父类代码；重写 `@Override`：改造父类方法。
- 接口 `interface` + `implements`：能力合同，一个类可实现多个接口。
- Forge 代码里到处是继承和接口——看不懂这一课，就看不懂 Forge。
