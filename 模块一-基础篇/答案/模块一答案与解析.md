## 第 01 课答案

**1.** 命令：`java -version`。成功时应看到 `openjdk version "17.0.x"`（关键是主版本号 **17**）。

**2.** Gradle 和 Forge 的构建工具链对非 ASCII 字符和空格的路径支持很差，会导致构建脚本报错、资源找不到等问题。规范做法：纯英文、无空格路径，如 `D:\ModDev\MyFirstMod`。

**3.** `runClient`（位于 Gradle 面板 Tasks → forgegradle runs 下）。

**4.** 需要改两处关键位置：`mods.toml` 里的 `modId="mycoolmod"`，以及 Java 主类里的 `MODID = "mycoolmod"`。运行后 Mods 列表里模组 ID 变为 mycoolmod。解析：这两处必须一致，Forge 靠它们把"档案表"和"代码"对应起来。

**5.** 参考思路：Java 程序不是直接在电脑上运行的，而是跑在 Java 虚拟机（JVM）上。不同版本的 JVM 支持的字节码版本、语法特性、核心类库都不同。Minecraft 1.20.1 官方就是基于 Java 17 开发的，Forge 也围绕它构建；版本高了或低了，类库对不上、字节码不兼容，就会构建失败。（模块三会深入讲解 JVM。）

## 第 02 课答案

**1.**
- `player1` ✅ 合法
- `1player` ❌ 不能以数字开头
- `player-name` ❌ 不能有连字符（会被当成减号）
- `playerName` ✅ 合法且符合驼峰规范
- `class` ❌ 是 Java 保留字
- `max_stack_size` ✅ 合法（但不符合 Java 驼峰习惯，这种写法在 Python 中更常见）

**2.**
- `17 / 5` → `3`（整数除法舍去小数）
- `17 % 5` → `2`
- `17.0 / 5` → `3.4`
- `(8 > 5) && (3 < 2)` → `false`（`3 < 2` 为假，"并且"一假即假）
- `!(10 == 10)` → `false`

**3.**

```java
int count = 64;
if (count >= 64) {
    System.out.println("已满组");
} else {
    System.out.println("未满");
}
```

**4.**

```java
for (int i = 1; i <= 100; i++) {
    if (i % 3 == 0) {
        System.out.println(i);
    }
}
```

**5.**

```java
int exp = 0;
while (exp / 10 < 5) {
    exp += 7;
    System.out.println("经验: " + exp + "，等级: " + (exp / 10));
}
```

注意循环条件是 `exp / 10 < 5`（等级未满 5 级时继续）。如果把 `exp += 7` 写在打印之后，第一圈会打印 0 经验，逻辑顺序要注意。

**6.** 这段代码**编译不通过**。`x = 6` 是赋值表达式，其值是 `6`（int 类型），而 Java 的 `if` 条件必须是 `boolean` 类型，所以编译器报错 "int cannot be converted to boolean"。解析：Java 用强类型检查在编译期就拦住了"把 `==` 误写成 `=`"这类 bug——这是 Java 比 C/C++ 安全的一个细节。

## 第 03 课答案

**1.** 返回值类型 `double`；方法名 `getAverage`；参数列表 `(int sum, int count)`。

**2.** 合法下标 `0`～`9`。访问 `arr[10]` 会在**运行时**抛出 `ArrayIndexOutOfBoundsException`（数组下标越界异常），程序崩溃。注意是运行时才发现，编译时不报错。

**3.** `.toUpperCase()` → `"MINECRAFT FORGE"`；`.substring(0, 9)` → `"Minecraft"`（含 0，不含 9）。

**4.**

```java
static int countMaxStack(int[] stacks) {
    int count = 0;
    for (int s : stacks) {
        if (s == 64) {
            count++;
        }
    }
    return count;
}
```

**5.**

```java
static String formatDamage(double damage) {
    return "攻击力: " + damage + " 点";
}
```

**6.**

```java
static String findStrongestTool(String[] tools, int[] damages) {
    if (tools.length == 0) {
        return "无工具";
    }
    int maxIndex = 0;
    for (int i = 1; i < tools.length; i++) {
        if (damages[i] > damages[maxIndex]) {
            maxIndex = i;
        }
    }
    return tools[maxIndex];
}
```

解析：经典"打擂台"算法——先假设第 0 个最强，逐个挑战，发现更强的就更新擂主下标。

## 第 04 课答案

**1.** 类是图纸/模板，描述一类事物的属性和行为；对象是按类创建的具体实例。例：`Item`（物品）是类，"我背包里那把耐久剩 100 的铁剑"是对象。一个类可造出无数对象，各对象属性独立。

**2.** `name` 是 `private` 的，类外部不能直接访问，编译报错。应提供 public 的 setter 或构造方法来设置。

**3.** `super`；第一行。

**4.**

```java
class Armor {
    private String name;
    private int defense;

    Armor(String name, int defense) {
        this.name = name;
        this.defense = defense;
    }

    public int getDefense() {
        return defense;
    }

    public void wear() {
        System.out.println("穿戴上 " + name + "，防御力 +" + defense);
    }
}
```

**5.**

```java
class Helmet extends Armor {
    Helmet(String name, int defense) {
        super(name, defense);
    }

    void waterBreathing() {
        System.out.println("水下呼吸生效！");
    }
}

public class Main {
    public static void main(String[] args) {
        Helmet h = new Helmet("海龟壳", 2);
        h.wear();             // 继承自 Armor
        h.waterBreathing();   // Helmet 独有
        System.out.println("防御力: " + h.getDefense());
    }
}
```

**6.**

```java
interface Enchantable {
    void enchant(String enchantName);
}

class Armor implements Enchantable {
    // ...原有代码不变，追加：
    @Override
    public void enchant(String enchantName) {
        System.out.println("为 " + name + " 附魔了 " + enchantName);
    }
}
```

（注意：实现接口方法时，若 `name` 在 Armor 里是 private 可直接用，因为方法就写在 Armor 内部。）

**7.** 如果允许多继承，两个父类有同名方法时，子类调用该方法会产生"到底执行谁"的二义性（菱形继承问题）。接口（在 Java 8 之前的传统用法中）只有方法签名没有实现，不携带具体代码，所以实现多个接口不会产生"执行谁"的冲突——实现由子类自己写。Java 用"单继承 + 多接口"在安全性和灵活性之间取得平衡。

## 第 05 课答案

**1.** 代码：`src/main/java`；资源：`src/main/resources`。

**2.** 全小写字母、数字、下划线，不能有空格和大写。`"mycoolmod"` 合法；`"MyCoolMod"` 有大写、`"my cool mod"` 有空格，都不合规。

**3.** `modId` 字段。不一致会导致 Forge 无法将 mods.toml 与模组类匹配，启动时报错（如模组信息显示异常或模组加载失败）。

**4.** 需要修改/创建的文件：
- 新建 `com/adventure/adventuremod/AdventureMod.java`（`@Mod("adventure")`，`MODID = "adventure"`）
- 修改 `mods.toml`：`modId="adventure"`、`displayName="Adventure Mod"`、`authors="你的名字"`
- 删除旧的 examplemod 包和类
- Mods 列表应显示 Adventure Mod。

**5.** 日志出现在 Forge 输出"构造模组"阶段附近（一般在大量 mod 发现、构造日志之中），早于注册阶段。这验证了：主类构造方法是模组生命周期的第一步。

**6.** 参考思路：模组不是独立程序，而是"寄生"在游戏里的插件——游戏本体控制启动流程，模组只能在游戏允许的时点介入；同时几十个模组共存，如果各自乱写执行流程会互相冲突。事件总线让 Forge 统一管理"什么时候谁能做什么"，模组只需订阅自己关心的事件，既安全又解耦。（这正是模块二事件系统的设计动机。）

## 第 06 课答案

**1.** ① 创建 DeferredRegister 登记表；② 用 `register("注册名", 制造方法)` 登记物品；③ 在主类构造方法中把登记表挂到模组事件总线。

**2.** 方块在世界中是一种"方块"，在背包里又是一种"物品"，两个花名册都要登记。多的一步是注册 BlockItem（方块对应的物品形态）。

**3.** `"magic_wand"` 合法。注册名必须全小写、无空格、无中文；`"MagicWand"` 含大写，`"魔法杖"` 是中文，都不合规。

**4.** 在 `ModItems` 中增加：

```java
public static final RegistryObject<Item> MAGIC_STICK =
        ITEMS.register("magic_stick",
                () -> new Item(new Item.Properties().stacksTo(1)));
```

运行后 `/give @p mycoolmod:magic_stick` 即可获得。

**5.** 在 `ModBlocks` 中增加：

```java
public static final RegistryObject<Block> MAGIC_ORE = registerBlock("magic_ore",
        () -> new Block(BlockBehaviour.Properties.copy(Blocks.DIAMOND_ORE)
                .strength(4.0f)
                .lightLevel(state -> 7)));
```

**6.** 可能出现初始化顺序相关的报错（如 ITEMS 登记表在使用时还未正确挂接、或注册时序异常，具体报错因版本而异，常见为 NullPointerException 或注册相关的 IllegalStateException）。原因：`registerBlock` 内部会调用 `ModItems.ITEMS.register(...)`，方块物品的注册依赖物品登记表已挂接到总线。顺序原则：先挂基础登记表（物品），再挂依赖它的（方块）。这体现了模组代码中"静态初始化顺序"的重要性——模块二还会再遇到。

## 第 07 课答案

**1.** `assets/mycoolmod/textures/item/` 目录，文件名 `magic_stick.png`。

**2.** `item` = 类型（物品）；`mycoolmod` = 模组 ID；`magic_stick` = 注册名。

**3.** 因为模型里写的是"资源路径"（ResourceLocation），是 Minecraft 内部的资源定位格式，不是真实文件路径。游戏会自己去 `textures/` 目录下找对应的 `.png` 文件，后缀由游戏自动补上。

**4.** 需要的文件清单：

```
assets/mycoolmod/
├── lang/zh_cn.json  追加：
│     "item.mycoolmod.magic_stick": "魔法棒",
│     "block.mycoolmod.magic_ore": "魔法矿石"
├── models/item/magic_stick.json   （parent: minecraft:item/generated，layer0 指向 mycoolmod:item/magic_stick）
├── models/block/magic_ore.json    （parent: minecraft:block/cube_all，all 指向 mycoolmod:block/magic_ore）
├── models/item/magic_ore.json     （parent: mycoolmod:block/magic_ore）
├── blockstates/magic_ore.json     （variants 空状态指向 mycoolmod:block/magic_ore）
├── textures/item/magic_stick.png
└── textures/block/magic_ore.png
```

创造栏事件里追加：魔法棒 → INGREDIENTS；魔法矿石 → NATURAL_BLOCKS。

**5.** 翻译键不匹配时，物品显示原始翻译键字符串（如 `item.mycoolmod.ruby`），呈灰色"未翻译"状态；贴图丢失时显示紫黑相间的方块（missing texture）。这两种现象是资源排查的标志性信号：名字怪 = 语言文件问题；紫黑块 = 贴图/模型问题。

**6.** 原版游戏同样使用资源包 + 语言文件机制（`assets/minecraft/lang/`），与模组完全同一套机制。事实上，模组资源就是作为"附加资源包"被加载进游戏的——这也是为什么模组的资源目录约定和原版资源包一模一样。

### LuckyClover.java（主类）

```java
package com.lucky.luckyclover;

import net.minecraft.world.item.CreativeModeTabs;
import net.minecraftforge.event.BuildCreativeModeTabContentsEvent;
import net.minecraftforge.eventbus.api.IEventBus;
import net.minecraftforge.fml.common.Mod;
import net.minecraftforge.fml.javafmlmod.FMLJavaModLoadingContext;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

@Mod(LuckyClover.MODID)
public class LuckyClover {
    public static final String MODID = "luckyclover";
    private static final Logger LOGGER = LoggerFactory.getLogger(LuckyClover.class);

    public LuckyClover() {
        LOGGER.info("幸运草模组加载完毕！");
        IEventBus modEventBus = FMLJavaModLoadingContext.get().getModEventBus();
        ModItems.register(modEventBus);
        ModBlocks.register(modEventBus);
        modEventBus.addListener(this::addCreative);
    }

    private void addCreative(BuildCreativeModeTabContentsEvent event) {
        if (event.getTabKey() == CreativeModeTabs.INGREDIENTS) {
            event.accept(ModItems.FOUR_LEAF_CLOVER);
        }
        if (event.getTabKey() == CreativeModeTabs.NATURAL_BLOCKS) {
            event.accept(ModBlocks.LUCKY_CLOVER_BLOCK);
        }
    }
}
```

### ModItems.java

```java
package com.lucky.luckyclover;

import net.minecraft.world.item.Item;
import net.minecraftforge.eventbus.api.IEventBus;
import net.minecraftforge.registries.DeferredRegister;
import net.minecraftforge.registries.ForgeRegistries;
import net.minecraftforge.registries.RegistryObject;

public class ModItems {
    public static final DeferredRegister<Item> ITEMS =
            DeferredRegister.create(ForgeRegistries.ITEMS, LuckyClover.MODID);

    public static final RegistryObject<Item> FOUR_LEAF_CLOVER =
            ITEMS.register("four_leaf_clover",
                    () -> new Item(new Item.Properties().stacksTo(16)));

    public static void register(IEventBus eventBus) {
        ITEMS.register(eventBus);
    }
}
```

### ModBlocks.java

```java
package com.lucky.luckyclover;

import net.minecraft.world.item.BlockItem;
import net.minecraft.world.item.Item;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.Blocks;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.minecraftforge.eventbus.api.IEventBus;
import net.minecraftforge.registries.DeferredRegister;
import net.minecraftforge.registries.ForgeRegistries;
import net.minecraftforge.registries.RegistryObject;

import java.util.function.Supplier;

public class ModBlocks {
    public static final DeferredRegister<Block> BLOCKS =
            DeferredRegister.create(ForgeRegistries.BLOCKS, LuckyClover.MODID);

    public static final RegistryObject<Block> LUCKY_CLOVER_BLOCK = registerBlock("lucky_clover_block",
            () -> new Block(BlockBehaviour.Properties.copy(Blocks.GRASS_BLOCK)
                    .lightLevel(state -> 7)));

    private static <T extends Block> RegistryObject<T> registerBlock(String name, Supplier<T> supplier) {
        RegistryObject<T> block = BLOCKS.register(name, supplier);
        ModItems.ITEMS.register(name, () -> new BlockItem(block.get(), new Item.Properties()));
        return block;
    }

    public static void register(IEventBus eventBus) {
        BLOCKS.register(eventBus);
    }
}
```

### 常见扣分点自查

- MODID、modId、assets 下的文件夹名三者是否完全一致？
