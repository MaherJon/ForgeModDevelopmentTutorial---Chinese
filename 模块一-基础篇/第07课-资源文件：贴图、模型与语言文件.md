# 第 07 课：资源文件——贴图、模型与语言文件

> 本课目标：让你的物品和方块"有名字、有长相"，并出现在创造模式物品栏里。
>
> 前置知识：第 06 课（已注册物品和方块）。

---

## 7.1 资源文件的"规定位置"

Minecraft 有一套**严格**的资源文件目录约定，放错位置游戏就找不到。以第 06 课的红宝石为例：

```
src/main/resources/
├── META-INF/mods.toml
├── pack.mcmeta
└── assets/                          ← 所有"游戏资源"的根目录
    └── mycoolmod/                   ← 你的模组 ID（必须一致！）
        ├── lang/                    ← 语言文件（翻译）
        │   ├── en_us.json           ← 英文（美国）
        │   └── zh_cn.json           ← 简体中文
        ├── models/                  ← 模型文件（形状）
        │   ├── item/ruby.json       ← 物品模型
        │   └── block/ruby_block.json← 方块模型
        ├── textures/                ← 贴图文件（皮肤）
        │   ├── item/ruby.png        ← 物品贴图
        │   └── block/ruby_block.png ← 方块贴图
        └── blockstates/             ← 方块状态映射
            └── ruby_block.json
```

> ⚠️ 三层对应关系必须一致：`mycoolmod` 是 MODID；`ruby` 是注册名；文件名和 JSON 里写的名字都要对得上。这套"约定大于配置"是 Minecraft 模组开发的铁律。

---

## 7.2 语言文件：给物品起名字

语言文件是 **JSON 格式**（一种"键: 值"的数据格式，键和值都要用英文双引号包起来）。

### `assets/mycoolmod/lang/zh_cn.json`

```json
{
  "item.mycoolmod.ruby": "红宝石",
  "block.mycoolmod.ruby_block": "红宝石块"
}
```

### `assets/mycoolmod/lang/en_us.json`

```json
{
  "item.mycoolmod.ruby": "Ruby",
  "block.mycoolmod.ruby_block": "Block of Ruby"
}
```

规律：翻译键 = `类型.模组ID.注册名`。物品用 `item.`，方块用 `block.`。

游戏根据玩家选择的语言自动加载对应文件。玩家选中文就看到"红宝石"，选英文就看到 "Ruby"——这就是**本地化（i18n）**。

> ⚠️ JSON 常见错误：多写了末尾逗号 `{ "a": "b", }`、用了中文引号 `“”`、忘了冒号。IDEA 会在出错处标红线，注意看。

## 7.3 贴图：给物品画皮肤

贴图是 **PNG 格式的图片**，物品通常是 16×16 像素（也可以是 32、64……，必须是 16 的倍数）。

获取贴图的三种方式：

1. **自己画**：推荐免费工具 [Piskel](https://www.piskelapp.com/)（网页版，无需安装）。新建 16×16 画布，画好后导出 PNG。
2. **用 IDEA 简单画**：右键 `textures/item` → New → File，文件名 `ruby.png`——IDEA 没有像素画功能，所以更推荐方式 1。
3. **改官方贴图**：开发环境的游戏资源里能找到原版贴图，复制一张改改颜色。

画好后，把 `ruby.png` 放到 `assets/mycoolmod/textures/item/` 目录下。

---

## 7.4 模型：告诉游戏"贴图怎么贴"

模型也是 JSON 文件，告诉游戏"这个物品用哪张贴图、什么形状"。

### 物品模型 `assets/mycoolmod/models/item/ruby.json`

```json
{
  "parent": "minecraft:item/generated",
  "textures": {
    "layer0": "mycoolmod:item/ruby"
  }
}
```

- `parent`：父模型（第 04 课继承的思想！）。`item/generated` 是原版提供的"扁平物品"模板，普通物品都继承它。
- `layer0`：第 0 层贴图，路径格式是 `模组ID:类别/文件名`（不带 .png 后缀）。

### 方块模型 `assets/mycoolmod/models/block/ruby_block.json`

```json
{
  "parent": "minecraft:block/cube_all",
  "textures": {
    "all": "mycoolmod:block/ruby_block"
  }
}
```

`cube_all` 表示"六个面用同一张贴图的立方体"（石头、铁块都是这种）。

### 方块状态映射 `assets/mycoolmod/blockstates/ruby_block.json`

方块在游戏里可能有不同状态（比如楼梯朝向不同）。普通方块只有一种状态，直接指到模型即可：

```json
{
  "variants": {
    "": { "model": "mycoolmod:block/ruby_block" }
  }
}
```

### 方块的物品形态模型 `assets/mycoolmod/models/item/ruby_block.json`

背包里的方块物品，直接"继承"方块模型：

```json
{
  "parent": "mycoolmod:block/ruby_block"
}
```

## 7.5 加入创造模式物品栏

现在物品有了名字和长相，但创造模式的物品栏里找不到它，只能 `/give`。想让它出现在物品栏，需要订阅一个事件（用到第 05 课的事件总线知识）：

在 `ModItems` 或主类中添加一个方法，并在构造方法里订阅：

```java
import net.minecraft.world.item.CreativeModeTabs;
import net.minecraftforge.event.BuildCreativeModeTabContentsEvent;

// 主类构造方法中：
public MyCoolMod() {
    IEventBus modEventBus = FMLJavaModLoadingContext.get().getModEventBus();
    ModItems.register(modEventBus);
    ModBlocks.register(modEventBus);

    // 订阅"填充创造模式物品栏"事件
    modEventBus.addListener(this::addCreative);
}

// 事件处理方法：把我们的内容加进"原材料"和"建筑方块"标签页
private void addCreative(BuildCreativeModeTabContentsEvent event) {
    if (event.getTabKey() == CreativeModeTabs.INGREDIENTS) {
        event.accept(ModItems.RUBY);        // 红宝石 → 原材料页
    }
    if (event.getTabKey() == CreativeModeTabs.BUILDING_BLOCKS) {
        event.accept(ModBlocks.RUBY_BLOCK); // 红宝石块 → 建筑方块页
    }
}
```

运行游戏，打开创造模式物品栏的"原材料"页，你的红宝石就在里面了！🎉

## 7.6 检查清单：资源不生效时的排查顺序

新手最常见的"紫黑块"（缺贴图）或"无名字"问题，按这个顺序查：

1. 目录层级对不对？（`assets/模组ID/textures/item/xxx.png`）
2. 文件名和注册名一致吗？大小写一致吗？（`Ruby.png` 和 `ruby` 不匹配！）
3. JSON 里的路径写对了吗？（`mycoolmod:item/ruby`，没有 .png）
4. JSON 语法有错误吗？（逗号、引号，IDEA 会标红）
5. 改完后重新运行游戏了吗？（资源改动有时需要重启 runClient）
6. 看日志！游戏控制台会打印 `Missing texture` 等黄色警告，指明哪个文件没找到。

---

## 7.7 本课小结

- 资源文件放在 `assets/模组ID/` 下，目录结构和命名有严格约定。
- 语言文件负责显示名，翻译键格式：`类型.模组ID.注册名`。
- 贴图是 PNG 文件，物品通常 16×16；模型 JSON 通过 `parent` 继承模板。
- 方块需要三个 JSON：blockstates 映射、block 模型、item 形态的模型。
- 用 `BuildCreativeModeTabContentsEvent` 事件把内容加入创造模式物品栏。

## 7.8 配套练习

> 答案见本模块 `答案/模块一答案与解析.md`。

**基础题**

1. 补全路径：注册名为 `magic_stick` 的物品，其贴图应放在 `assets/mycoolmod/______/______/` 目录下，文件名为 ______。
2. 翻译键 `item.mycoolmod.magic_stick` 的三个部分分别代表什么？
3. 物品模型 JSON 里 `"layer0": "mycoolmod:item/ruby"` 为什么不写 `.png` 后缀？

**提高题**

4. 为第 06 课练习中的 `magic_stick` 和 `magic_ore` 配齐全部资源文件（语言、模型、贴图、blockstates），让它们在游戏里正常显示中文名和贴图，并加入合适的创造模式标签页。
5. 故意"制造 bug"练习排错：把 `zh_cn.json` 里的 `ruby` 改成 `ruby2`（翻译键不匹配），运行游戏观察红宝石显示成什么样；然后改回来。再试着把贴图文件改个名，观察紫黑块。记录两种问题的不同表现。
6. 思考题：原版 Minecraft 的"钻石剑"翻译成中文是"钻石剑"、英文是 "Diamond Sword"。结合本课知识，推测原版游戏是怎么实现多语言的？你的模组和原版用的是同一套机制吗？
