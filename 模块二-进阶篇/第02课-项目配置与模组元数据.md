## 2.1 mods.toml：模组的"档案表"

玩家在 Mods 列表里看到的名字、介绍、作者、logo，全部来自 `src/main/resources/META-INF/mods.toml`。它用 **TOML** 格式书写——一种比 JSON 更适合人读写的配置格式。

### TOML 语法速成（30 秒）

```toml
# 这是注释
key = "value"          # 键 = 值
version = "1.0.0"      # 字符串用双引号
number = 47            # 数字不加引号

[section]              # 一个"小节"
[[mods]]               # 双方括号：表示"列表中的一项"，可以写多个 [[mods]]
```

### 完整字段逐行讲解

```toml
modLoader="javafml"            # 加载器类型，Forge 模组固定写 javafml
loaderVersion="[47,)"          # 需要的 Forge 版本范围：[47,) 表示 47 及以上
license="MIT"                  # 开源协议（你的代码允许别人怎么用）
issueTrackerURL="https://github.com/你的名字/仓库/issues"   # 问题反馈地址（可选）

[[mods]]
    modId="mycoolmod"          # 模组 ID，必须和 @Mod 注解一致
    version="1.0.0"            # 版本号
    displayName="My Cool Mod"  # 显示名（可以用空格和大写）
    authors="小明"              # 作者
    credits="感谢 XXX 的贴图"   # 鸣谢（可选）
    description='''            # 模组介绍（三引号可写多行）
一个有趣的模组，
添加了红宝石！
'''
    logoFile="logo.png"        # 模组 logo（可选，图片放 resources 根目录）
    displayURL="https://..."   # 主页链接（可选）
```

> 💡 **版本范围写法**：`[47,)` = 47 及以上；`[47,48)` = 47 到 48（不含 48）；`[47.2.0,)` = 精确到小版本。方括号含、圆括号不含。

### 声明模组依赖（前置模组）

如果你的模组需要"另一个模组先装好才能运行"，用 `dependencies` 声明：

```toml
[[dependencies.mycoolmod]]
    modId="forge"              # 依赖 forge 本体
    mandatory=true             # 是否强制（true=缺了就进不了游戏）
    versionRange="[47,)"
    ordering="NONE"
    side="BOTH"                # 在哪一端需要：CLIENT / SERVER / BOTH
```

好处：玩家缺前置时，游戏会弹出友好提示"缺少 xx 模组"，而不是神秘崩溃。

## 2.2 pack.mcmeta：资源包的"说明书"

`src/main/resources/pack.mcmeta` 内容很简单：

```json
{
  "pack": {
    "description": "mycoolmod resources",
    "pack_format": 15
  }
}
```

- `description`：资源包描述；
- `pack_format`：**资源包格式版本号**，必须和游戏版本匹配，1.20.1 对应 **15**。写错了游戏会提示"资源包版本不兼容"。

> 💡 你模组的 assets 本质上就是一个内嵌的资源包，所以它也需要一份 pack.mcmeta。

## 2.3 多环境概念：客户端 vs 服务端

Minecraft 是"客户端 + 服务端"架构。有些代码只能在特定一端运行：

- **客户端专属**：渲染、贴图、粒子、按键（"画面相关"）；
- **服务端专属**：世界生成、存档逻辑（"数据相关"）；
- **两端都有**：物品注册、游戏逻辑。

如果服务端执行了渲染代码，会直接崩溃（服务器没有屏幕！）。Forge 用注解帮你隔离：

```java
@Mod.EventBusSubscriber(modid = MyCoolMod.MODID, value = Dist.CLIENT)
public class ClientEvents {
    // 这个类里的代码只会在客户端加载
}
```

> ⚠️ 这是进阶期最容易踩的坑之一：**在服务端误用客户端类**。症状是"单人游戏好好的，开服务器就崩"。第 05 课和第 07 课会反复用到 `Dist` 概念。

---

## 2.4 本课小结

- `mods.toml` 是模组档案：`modId`（与代码一致）、`displayName`、`description`、`authors` 等控制 Mods 列表展示。
- `loaderVersion` 和 `dependencies` 用版本范围语法声明兼容性，避免玩家装错环境。
- `pack.mcmeta` 的 `pack_format` 必须与游戏版本对应（1.20.1 = 15）。
- 模组代码分客户端/服务端两端，用 `Dist` 隔离，防止服务端执行渲染代码导致崩溃。
