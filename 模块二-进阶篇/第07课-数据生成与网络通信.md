## 7.1 数据生成（DataGen）：用代码写 JSON

### 为什么需要 DataGen？

第 07 课（模块一）我们手写了大量 JSON：语言文件、模型、blockstates……一个方块要 3～4 个 JSON。如果你的模组有 100 个方块呢？手写会死人，改起来更是噩梦。

**DataGen 的思想**：JSON 是"死"的，但生成 JSON 的逻辑是"活"的。写一段 Java 代码描述"我的方块都用 cube_all 模型"，运行一次，几百个 JSON 自动生成。改模板 → 重新生成 → 全部更新。

```
你写的 DataGen 代码 → 运行 runData → 自动生成到 src/generated/resources/
```

### 第 1 步：写一个数据生成入口类

```java
package com.mycooldev.mycoolmod.datagen;

import com.mycooldev.mycoolmod.MyCoolMod;
import net.minecraft.data.DataGenerator;
import net.minecraft.data.PackOutput;
import net.minecraftforge.common.data.ExistingFileHelper;
import net.minecraftforge.data.event.GatherDataEvent;
import net.minecraftforge.eventbus.api.SubscribeEvent;
import net.minecraftforge.fml.common.Mod;

// 注意：这是"模组总线"事件！游戏启动加载阶段的事
@Mod.EventBusSubscriber(modid = MyCoolMod.MODID, bus = Mod.EventBusSubscriber.Bus.MOD)
public class DataGenerators {

    @SubscribeEvent
    public static void gatherData(GatherDataEvent event) {
        DataGenerator generator = event.getGenerator();
        PackOutput packOutput = generator.getPackOutput();
        ExistingFileHelper existingFileHelper = event.getExistingFileHelper();

        // 把我们的生成器挂上去（下一步就写它）
        generator.addProvider(event.includeClient(),
                new ModBlockStateProvider(packOutput, MyCoolMod.MODID, existingFileHelper));
        generator.addProvider(event.includeClient(),
                new ModItemModelProvider(packOutput, MyCoolMod.MODID, existingFileHelper));
    }
}
```

### 第 2 步：写具体的生成器

**方块模型生成器**（自动生成 blockstates + 方块模型 + 方块物品模型）：

```java
package com.mycooldev.mycoolmod.datagen;

import com.mycooldev.mycoolmod.ModBlocks;
import net.minecraft.data.PackOutput;
import net.minecraftforge.client.model.generators.BlockStateProvider;
import net.minecraftforge.common.data.ExistingFileHelper;

public class ModBlockStateProvider extends BlockStateProvider {

    public ModBlockStateProvider(PackOutput output, String modid, ExistingFileHelper exFileHelper) {
        super(output, modid, exFileHelper);
    }

    @Override
    protected void registerStatesAndModels() {
        // simpleBlockWithItem：一行搞定方块的 blockstates + 模型 + 物品模型！
        simpleBlockWithItem(ModBlocks.RUBY_BLOCK.get(),
                cubeAll(ModBlocks.RUBY_BLOCK.get()));
        // 你有一百个方块？循环一百次就行，这就是代码的力量
    }
}
```

**物品模型生成器**：

```java
package com.mycooldev.mycoolmod.datagen;

import com.mycooldev.mycoolmod.ModItems;
import net.minecraft.data.PackOutput;
import net.minecraft.resources.ResourceLocation;
import net.minecraftforge.client.model.generators.ItemModelProvider;
import net.minecraftforge.common.data.ExistingFileHelper;

public class ModItemModelProvider extends ItemModelProvider {

    public ModItemModelProvider(PackOutput output, String modid, ExistingFileHelper exFileHelper) {
        super(output, modid, exFileHelper);
    }

    @Override
    protected void registerModels() {
        // basicItem：生成"继承 item/generated、贴图同名"的标准物品模型
        basicItem(ModItems.RUBY.get());
    }
}
```

### 第 3 步：运行 runData

Gradle 面板运行 `runData` 任务，成功后在 `src/generated/resources/assets/mycoolmod/` 下就能看到自动生成的 JSON——和手写的一模一样，但是代码生成的。

> 💡 DataGen 还能生成语言文件、合成表、战利品表、标签等。Forge 提供了 `LanguageProvider`、`RecipeProvider`、`LootTableProvider` 等一堆 Provider，用法相同：继承 → 重写注册方法 → 挂到 gatherData。

## 7.2 网络通信：客户端与服务端对话

### 什么时候需要网络包？

上一课说过：逻辑在服务端，显示在客户端。两端是"两个世界"，只能靠**网络数据包**通信。典型场景：

- 客户端玩家按了一个键 → 发包告诉服务端"他按键了" → 服务端执行技能；
- 服务端数据变了 → 发包告诉客户端"数据是 X 了" → 客户端更新界面。

原版已经帮你处理了大量同步（如普通方块状态），但**自定义数据**（比如你的技能冷却时间）必须自己发包。

### 第 1 步：创建网络通道（SimpleChannel）

```java
package com.mycooldev.mycoolmod.network;

import com.mycooldev.mycoolmod.MyCoolMod;
import net.minecraft.resources.ResourceLocation;
import net.minecraftforge.network.NetworkRegistry;
import net.minecraftforge.network.simple.SimpleChannel;

public class ModMessages {

    private static int packetId = 0;
    private static int id() {
        return packetId++;
    }

    public static final SimpleChannel INSTANCE = NetworkRegistry.newSimpleChannel(
            new ResourceLocation(MyCoolMod.MODID, "messages"),   // 通道名
            () -> "1.0",         // 协议版本
            "1.0"::equals,       // 客户端协议检查
            "1.0"::equals        // 服务端协议检查
    );
}
```

### 第 2 步：定义一个数据包

数据包 = 一个类，规定"包里装什么、怎么编码、怎么解码、收到后干什么"。

```java
package com.mycooldev.mycoolmod.network;

import net.minecraft.network.FriendlyByteBuf;
import net.minecraft.network.chat.Component;
import net.minecraft.server.level.ServerPlayer;
import net.minecraftforge.network.NetworkEvent;

import java.util.function.Supplier;

// 示例包：客户端发给服务端，请求"给我一颗红宝石"
public class GiveRubyPacket {

    public GiveRubyPacket() {
    }

    // 编码：把包内容写进字节流（本包没数据，什么都不写）
    public void encode(FriendlyByteBuf buffer) {
    }

    // 解码：从字节流读出一个包对象（必须和编码对应）
    public static GiveRubyPacket decode(FriendlyByteBuf buffer) {
        return new GiveRubyPacket();
    }

    // 处理：收到包后干什么（在服务端线程执行）
    public static void handle(GiveRubyPacket packet, Supplier<NetworkEvent.Context> contextSupplier) {
        NetworkEvent.Context context = contextSupplier.get();
        context.enqueueWork(() -> {
            ServerPlayer player = context.getSender();   // 发包的玩家
            if (player != null) {
                player.getInventory().add(new net.minecraft.world.item.ItemStack(
                        com.mycooldev.mycoolmod.ModItems.RUBY.get()));
                player.sendSystemMessage(Component.literal("已发放红宝石！"));
            }
        });
        context.setPacketHandled(true);
    }
}
```

三个固定套路：

1. `encode`：包 → 字节（写进 buffer）；
2. `decode`：字节 → 包（从 buffer 读，顺序必须与 encode 一致）；
3. `handle`：`enqueueWork` 里写真正的逻辑；最后 `setPacketHandled(true)`。

### 第 3 步：注册包 & 发送包

在 `ModMessages` 中加一个注册方法，并在 commonSetup 里调用：

```java
public static void register() {
    INSTANCE.messageBuilder(GiveRubyPacket.class, id(), net.minecraftforge.network.NetworkDirection.PLAY_TO_SERVER)
            .encoder(GiveRubyPacket::encode)
            .decoder(GiveRubyPacket::decode)
            .consumerMainThread(GiveRubyPacket::handle)
            .add();
}
```

主类里：

```java
public MyCoolMod() {
    IEventBus modEventBus = FMLJavaModLoadingContext.get().getModEventBus();
    // ...注册物品方块...
    modEventBus.addListener(this::commonSetup);
}

private void commonSetup(final FMLCommonSetupEvent event) {
    ModMessages.register();
}
```

发送（例如在某个按键事件或 GUI 按钮回调里，客户端执行）：

```java
ModMessages.INSTANCE.sendToServer(new GiveRubyPacket());
```

> ⚠️ `handle` 里的代码跑在**收到包的一端**。发给服务端的包，handle 在服务端执行——可以用 `context.getSender()` 拿玩家；发给客户端的包，handle 在客户端执行——那里才有画面相关的能力。

## 7.3 本课小结

- DataGen 用 Java 代码批量生成 JSON 资源；入口是模组总线的 `GatherDataEvent`，运行 `runData` 任务执行生成，产物在 `src/generated/resources/`。
- `simpleBlockWithItem`、`basicItem` 一行生成常用模型，方块越多收益越大。
- 网络通信三件套：SimpleChannel（通道）、数据包类（encode/decode/handle）、注册与发送。
- 自定义数据的两端同步必须自己发包；handle 在收包端执行。

**提高题**
