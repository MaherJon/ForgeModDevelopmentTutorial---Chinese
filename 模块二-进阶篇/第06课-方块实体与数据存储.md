# 第 06 课：方块实体（BlockEntity）与数据存储

> 本课目标：让方块"有记忆"——学会用 BlockEntity 给方块存数据，并用 NBT 把数据保存到存档里。
>
> 前置知识：模块一第 06 课（方块注册）、本模块第 05 课（事件）。

---

## 6.1 为什么需要 BlockEntity？

普通方块（`Block`）有个致命特点：**同一种方块的所有个体共享一份代码**。全世界的石头都是同一个 `Blocks.STONE` 对象，区别仅在于摆放位置。

但箱子、熔炉不一样——**每个箱子有自己的物品栏，每个熔炉有自己的烧制进度**。这种"每个个体都有自己的数据"的需求，就要靠 **BlockEntity（方块实体）**：

| | Block（方块） | BlockEntity（方块实体） |
|---|---|---|
| 类比 | 小区户型图（所有住户共用） | 每户自家的户口本（一户一份） |
| 数据 | 所有个体共享 | 每个位置的方块各有一份 |
| 例子 | 石头、泥土 | 箱子、熔炉、告示牌 |

> 💡 判断标准：方块**是否需要记住属于自己的数据**？需要 → BlockEntity。

## 6.2 认识 NBT：Minecraft 的数据格式

BlockEntity 的数据最终要存进存档文件，Minecraft 用的是 **NBT（Named Binary Tag）** 格式。在代码里它体现为 `CompoundTag` 类——一个键值对容器（想想第 03 课的 Map）：

```java
CompoundTag tag = new CompoundTag();
tag.putInt("counter", 42);           // 存整数
tag.putString("owner", "小明");       // 存字符串
tag.putBoolean("locked", false);     // 存布尔值

int counter = tag.getInt("counter");       // 读整数
String owner = tag.getString("owner");     // 读字符串
```

**存的时候叫什么键，取的时候就得用什么键**——"counter" 存进去，`getInt("counter")` 取出来。

## 6.3 实战：一个"计数器方块"

目标：做一个方块，玩家每次右键它，它就把自己被右键的次数 +1 并告诉玩家；**退出游戏重进后次数还在**。

### 第 1 步：写 BlockEntity 类

```java
package com.mycooldev.mycoolmod.blockentity;

import net.minecraft.core.BlockPos;
import net.minecraft.nbt.CompoundTag;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.state.BlockState;

public class CounterBlockEntity extends BlockEntity {

    private int counter = 0;   // 每个方块实体各自拥有的数据

    public CounterBlockEntity(BlockPos pos, BlockState state) {
        super(ModBlockEntities.COUNTER_BLOCK_ENTITY.get(), pos, state);
    }

    public void increment() {
        counter++;
        setChanged();   // ⚠️ 关键：告诉游戏"我的数据变了，需要保存"
    }

    public int getCounter() {
        return counter;
    }

    // ---- 数据保存：游戏存档时调用，把数据写进 NBT ----
    @Override
    protected void saveAdditional(CompoundTag tag) {
        super.saveAdditional(tag);
        tag.putInt("counter", counter);
    }

    // ---- 数据读取：游戏读档时调用，从 NBT 恢复数据 ----
    @Override
    public void load(CompoundTag tag) {
        super.load(tag);
        counter = tag.getInt("counter");
    }
}
```

两个重写方法对应"存"和"取"，`setChanged()` 是存档系统的"脏标记"——不调用它，游戏认为数据没变，可能不会保存。

### 第 2 步：注册 BlockEntity 类型

新建 `ModBlockEntities`：

```java
package com.mycooldev.mycoolmod.blockentity;

import com.mycooldev.mycoolmod.ModBlocks;
import com.mycooldev.mycoolmod.MyCoolMod;
import net.minecraft.world.level.block.entity.BlockEntityType;
import net.minecraftforge.eventbus.api.IEventBus;
import net.minecraftforge.registries.DeferredRegister;
import net.minecraftforge.registries.ForgeRegistries;
import net.minecraftforge.registries.RegistryObject;

public class ModBlockEntities {

    public static final DeferredRegister<BlockEntityType<?>> BLOCK_ENTITIES =
            DeferredRegister.create(ForgeRegistries.BLOCK_ENTITY_TYPES, MyCoolMod.MODID);

    public static final RegistryObject<BlockEntityType<CounterBlockEntity>> COUNTER_BLOCK_ENTITY =
            BLOCK_ENTITIES.register("counter_block_entity",
                    () -> BlockEntityType.Builder.of(
                            CounterBlockEntity::new,          // 构造方法引用
                            ModBlocks.COUNTER_BLOCK.get()     // 关联哪个方块
                    ).build(null));

    public static void register(IEventBus eventBus) {
        BLOCK_ENTITIES.register(eventBus);
    }
}
```

别忘记主类构造方法里加 `ModBlockEntities.register(modEventBus);`（放在 ModItems、ModBlocks 之后）。

### 第 3 步：写一个"带实体"的方块类

普通 `Block` 不会自动拥有 BlockEntity，要用 `BaseEntityBlock`：

```java
package com.mycooldev.mycoolmod.block;

import com.mycooldev.mycoolmod.blockentity.CounterBlockEntity;
import net.minecraft.core.BlockPos;
import net.minecraft.network.chat.Component;
import net.minecraft.world.InteractionHand;
import net.minecraft.world.InteractionResult;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.level.Level;
import net.minecraft.world.level.block.BaseEntityBlock;
import net.minecraft.world.level.block.RenderShape;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.state.BlockState;
import net.minecraft.world.phys.BlockHitResult;
import org.jetbrains.annotations.Nullable;

public class CounterBlock extends BaseEntityBlock {

    public CounterBlock(Properties properties) {
        super(properties);
    }

    // ① 告诉游戏：这个位置需要创建一个什么样的 BlockEntity
    @Nullable
    @Override
    public BlockEntity newBlockEntity(BlockPos pos, BlockState state) {
        return new CounterBlockEntity(pos, state);
    }

    // ② 玩家右键方块时的逻辑
    @Override
    public InteractionResult use(BlockState state, Level level, BlockPos pos,
                                 Player player, InteractionHand hand, BlockHitResult hit) {
        // 只在服务端改数据（客户端是"影子"，改了不算数，详见 6.4 节）
        if (!level.isClientSide()) {
            BlockEntity blockEntity = level.getBlockEntity(pos);
            if (blockEntity instanceof CounterBlockEntity counterBE) {
                counterBE.increment();
                player.sendSystemMessage(Component.literal(
                        "这个方块被右键了 " + counterBE.getCounter() + " 次"));
            }
        }
        return InteractionResult.SUCCESS;
    }

    // ③ BaseEntityBlock 默认要求自定义渲染方式，普通立方体方块要补这个
    @Override
    public RenderShape getRenderShape(BlockState state) {
        return RenderShape.MODEL;
    }
}
```

### 第 4 步：把方块注册改成新方块类

在 `ModBlocks` 中：

```java
public static final RegistryObject<Block> COUNTER_BLOCK = registerBlock("counter_block",
        () -> new CounterBlock(BlockBehaviour.Properties.copy(Blocks.STONE)));
```

配上语言文件、模型、贴图（模块一流程），运行游戏：放下方块，疯狂右键它，然后退出重进——次数还在！🎉

## 6.4 客户端与服务端：为什么要在 `!isClientSide()` 里改数据

Minecraft 单人游戏也是"内嵌服务端 + 客户端"两个世界在跑：

- **服务端**：权威世界，真正决定数据和规则；
- **客户端**：负责画面和输入，是服务端的"影子"。

如果你在客户端把计数 +1，服务端根本不知道，重进游戏就还原了。正确姿势永远是：**逻辑改服务端，显示走客户端**，两端通过数据包同步（下一课讲网络通信）。

`level.isClientSide()` 为 `true` 表示当前代码跑在客户端。所以"改数据"的代码放在 `!isClientSide()` 分支里。

---

## 6.5 本课小结

- 需要"每个个体独立数据"的方块 → 用 BlockEntity；它随方块位置一对一存在。
- 数据保存靠 NBT（`CompoundTag`）：`saveAdditional` 写入、`load` 读回；改完数据必须 `setChanged()`。
- 带实体的方块继承 `BaseEntityBlock`，重写 `newBlockEntity`；交互逻辑重写 `use` 方法。
- 数据修改必须在服务端进行（`!level.isClientSide()`）。
