# 模块二 · 答案与解析

> 先独立完成练习和项目，再来看答案。

## 第 01 课答案

**1.** `plugins`：为构建增加能力（如 Java 编译、ForgeGradle）；`dependencies`：声明工程依赖的外部代码库；`runs`：定义运行配置（客户端/服务端等）。

**2.** 命令：`gradlew build`。产物在 `build/libs/` 目录。

**3.** `com.google.guava` 是组（groupId），`guava` 是名称（artifactId），`33.0.0-jre` 是版本。

**4.** 修改 `build.gradle` 中 `version = '1.1.0'`，执行 `gradlew build`（或 Gradle 面板双击 build），在 `build/libs/` 下生成 `模组名-1.1.0.jar`。

**5.** 在 `runs {}` 中复制 client 段并改名：

```groovy
server {
    workingDirectory project.file('run')
    mods {
        mycoolmod {
            source sourceSets.main
        }
    }
}
```

刷新后出现 `runServer` 任务，启动后控制台输出 "Done" 即成功。

**6.** 手动管理 jar 的痛点：① 版本升级要重新全网找 jar；② 依赖的依赖（传递依赖）根本数不清；③ 多人协作时每个人版本可能不一致；④ 入库让仓库臃肿。Gradle 用一行坐标声明依赖，自动解析传递依赖、统一下载、保证团队环境一致、升级只改版本号。

## 第 02 课答案

**1.** 含义：需要 Forge 版本 47 或更高。玩家用 Forge 46 运行时，游戏启动阶段就会提示模组与加载器版本不兼容，拒绝加载（友好报错而不是莫名崩溃）。

**2.** `displayName` 控制显示名称；`modId` 控制模组 ID（且必须与 `@Mod` 一致）。

**3.** 游戏会把该资源视为"版本不兼容"的资源包，可能在日志中警告，资源可能不被加载。

**4.** 关键配置示例：

```toml
displayName="My Cool Mod"
authors="小明"
description='''
第一行介绍。
第二行介绍。
'''
logoFile="logo.png"
```

`logo.png` 放在 `src/main/resources/` 根目录。Mods 列表点进模组即可看到 logo 和介绍。

**5.**

```toml
[[dependencies.mycoolmod]]
    modId="minecraft"
    mandatory=true
    versionRange="[1.20.1,1.21)"
    ordering="NONE"
    side="BOTH"
```

**6.** 服务端没有渲染环境，执行粒子代码会因找不到客户端类而崩溃（`NoClassDefFoundError` 之类）。避免方法：渲染/粒子逻辑只在 `Dist.CLIENT` 环境中加载执行（如用 `@Mod.EventBusSubscriber(value = Dist.CLIENT)`），或在逻辑中判断 `level.isClientSide()`。

## 第 03 课答案

**1.** 泛型参数只能是引用类型（类），不能是基本类型。应写 `List<Integer>`。

**2.** 返回 `null`。直接对返回值调用方法或自动拆箱会抛 `NullPointerException`。应先判空或用 `map.getOrDefault(key, 0)`。

**3.** 选 `Set`（如 `HashSet`），它天然去重。

**4.**

```java
static Map<String, Integer> countDrops(List<String> drops) {
    Map<String, Integer> result = new HashMap<>();
    for (String drop : drops) {
        result.put(drop, result.getOrDefault(drop, 0) + 1);
    }
    return result;
}
```

解析：`getOrDefault(键, 默认值)`——查不到时返回默认值 0，巧妙避开 null 判断。

**5.**

```java
List<Integer> levels = new ArrayList<>(List.of(5, 12, 30, 8, 25));
levels.sort((a, b) -> b - a);   // b - a 即降序
System.out.println(levels);     // [30, 25, 12, 8, 5]
```

**6.**

```java
long count = List.of(5, 12, 30, 8, 25).stream()
        .filter(level -> level >= 10)
        .count();
System.out.println(count);   // 3
```

**7.** `<T extends Block>` 声明了一个类型参数 T，要求它必须是 Block 或其子类。好处：返回值保持具体类型——注册 RubyBlock 得到 `RegistryObject<RubyBlock>`，而不是笼统的 `RegistryObject<Block>`，调用方不用强制类型转换，编译期类型安全。这就是泛型方法的价值。

## 第 04 课答案

**1.** 告诉编译器"本方法重写了父类方法"，编译器会检查签名是否真的匹配。不写它也能运行，但若把方法名/参数写错，会悄悄变成一个新方法而不是重写，bug 难以发现。

**2.** 受检异常：编译器强制处理（不 catch 或声明 throws 就编译不过），多由外部环境引起，如 `IOException`；运行时异常：编译器不强制，多为代码 bug，如 `NullPointerException`、`ArrayIndexOutOfBoundsException`。

**3.** 空 catch 块：出错了完全不处理、不记录，问题被静默吞掉，日后无法排查。至少应打印日志（`e.printStackTrace()` 或 LOGGER.error）。

**4.**

```java
static int parseLevel(String input) {
    try {
        return Integer.parseInt(input);
    } catch (NumberFormatException e) {
        return -1;
    }
}
```

**5.**

```java
void setStackSize(Item.Properties props, int size) {
    if (size < 1 || size > 64) {
        throw new IllegalArgumentException("堆叠数必须在 1~64 之间，当前: " + size);
    }
    props.stacksTo(size);
}
```

**6.**

```java
public class ReflectionDemo {
    public static void main(String[] args) throws Exception {
        Class<?> clazz = Class.forName("com.example.Hello");
        Object obj = clazz.getDeclaredConstructor().newInstance();
        clazz.getMethod("sayHi").invoke(obj);
    }
}

class Hello {
    public Hello() {}
    public void sayHi() {
        System.out.println("hi!");
    }
}
```

**7.** 配置登记方式：优点是显式、好排查；缺点是每次新建/改名主类都要同步改配置，容易遗忘，且配置和代码可能不一致。运行时扫描注解：优点是约定大于配置——标签就贴在类上，永远同步，几十个模组各自贴标签互不影响；缺点是有扫描成本、出错时线索不如显式配置直观。Forge 选择注解是因为模组数量多、开发者水平不一，"贴着代码走"的方案出错率最低。

## 第 05 课答案

**1.** `BuildCreativeModeTabContentsEvent` → 模组总线（加载期）；`LivingHurtEvent` → Forge 总线（运行时）。

**2.** 必须是 `public static`，参数为对应的事件类型，方法上加 `@SubscribeEvent`。

**3.** `event.setCanceled(true)`（前提是该事件支持取消，即继承自 ICancellableEvent / 有 setCanceled 方法）。

**4.**

```java
@Mod.EventBusSubscriber(modid = MyCoolMod.MODID)
public class DeathEvents {
    @SubscribeEvent
    public static void onDeath(LivingDeathEvent event) {
        if (event.getEntity() instanceof Player player) {
            player.sendSystemMessage(Component.literal(
                    "玩家 " + player.getName().getString() + " 倒下了！"));
        }
    }
}
```

**5.**

```java
@Mod.EventBusSubscriber(modid = MyCoolMod.MODID, value = Dist.CLIENT)   // 提示只在客户端存在
public class TooltipEvents {
    @SubscribeEvent
    public static void onTooltip(ItemTooltipEvent event) {
        if (event.getItemStack().is(ModItems.RUBY.get())) {
            event.getToolTip().add(Component.literal("一块闪耀着幸运光芒的宝石"));
        }
    }
}
```

**6.**

```java
@SubscribeEvent
public static void onBreak(BlockEvent.BreakEvent event) {
    if (event.getState().is(BlockTags.LOGS)) {
        event.getPlayer().drop(new ItemStack(ModItems.RUBY.get()), false);
    }
}
```

（`player.drop(...)` 在玩家位置扔出物品实体，效果等同掉落。）

**7.** 每秒 20 次的高频事件里做耗时操作会直接拖慢主线程，导致 TPS 下降、游戏卡顿。启示：Tick 类事件里只做轻量判断；耗时操作应计数降频（如每 20 tick 才执行一次）或移出主线程；事件处理总体原则——能早返回就早返回，能少做事就少做事。

## 第 06 课答案

**1.** 当方块需要存储"每个放置个体各自独立的数据"时。原版例子：箱子（各自的物品栏）、熔炉（各自的烧制进度）、告示牌（各自的文字）。

**2.** 标记数据已修改，通知游戏需要保存/同步。忘记调用可能导致改动不被写入存档（退出重进数据还原）或客户端不同步。

**3.** 服务端是权威世界。在客户端改的数据只是"影子"，不会写进存档、也不会被其他玩家看到，且会被服务端同步覆盖。所以逻辑改动必须在服务端（`!isClientSide()`）执行。

**4.** 在 `use` 方法的服务端分支中：

```java
if (player.isShiftKeyDown()) {
    counterBE.reset();          // BE 中新增：counter = 0; setChanged();
    player.sendSystemMessage(Component.literal("计数已重置"));
} else {
    counterBE.increment();
    player.sendSystemMessage(Component.literal(
            "这个方块被右键了 " + counterBE.getCounter() + " 次"));
}
```

**5.** BE 中增加 `private String owner = "";`，`saveAdditional` 里 `tag.putString("owner", owner)`，`load` 里 `owner = tag.getString("owner", "")`。逻辑：

```java
if (counterBE.getOwner().isEmpty()) {
    counterBE.setOwner(player.getName().getString());
    player.sendSystemMessage(Component.literal("你成为了这个计数器的主人"));
} else if (!counterBE.getOwner().equals(player.getName().getString())) {
    player.sendSystemMessage(Component.literal("这是 " + counterBE.getOwner() + " 的计数器"));
}
```

（每次修改 owner 后记得 setChanged()。）

**6.** Block 是全类共享的单例——全世界的同种方块共用一个对象。若把计数存在 Block 字段里，所有位置的计数器方块会共享同一个计数（甲方块点 1 次，乙方块也 +1），且字段只活在内存中，退出游戏全部丢失。这正是 BlockEntity 存在的意义：按位置隔离数据 + 可持久化。

## 第 07 课答案

**1.** 优势：批量生成、改一处模板全量更新、减少手写 JSON 的格式错误、可用循环/条件等编程能力。生成目录：`src/generated/resources/`。

**2.** 模组总线（`Bus.MOD`）。因为数据生成是"启动/构建阶段"的工作，不是游戏运行中的事件。

**3.** 解码顺序必须与编码顺序严格一致：encode 先写什么，decode 就先读什么，类型也要一一对应。

**4.** 在 `ModBlockStateProvider.registerStatesAndModels()` 中加：

```java
simpleBlockWithItem(ModBlocks.COUNTER_BLOCK.get(), cubeAll(ModBlocks.COUNTER_BLOCK.get()));
```

运行 `runData`，检查 `src/generated/resources/assets/mycoolmod/` 下生成了 blockstates、models/block、models/item 三个 JSON。删除手写 JSON 后游戏内显示应依旧正常（确保 src/generated 被作为资源目录加载——MDK 默认已配置）。

**5.**

```java
public class FlyPacket {
    public FlyPacket() {}
    public void encode(FriendlyByteBuf buf) {}
    public static FlyPacket decode(FriendlyByteBuf buf) { return new FlyPacket(); }

    public static void handle(FlyPacket packet, Supplier<NetworkEvent.Context> ctx) {
        NetworkEvent.Context context = ctx.get();
        context.enqueueWork(() -> {
            ServerPlayer player = context.getSender();
            if (player != null) {
                player.getAbilities().mayfly = !player.getAbilities().mayfly;
                player.onUpdateAbilities();
            }
        });
        context.setPacketHandled(true);
    }
}
```

注册：

```java
INSTANCE.messageBuilder(FlyPacket.class, id(), NetworkDirection.PLAY_TO_SERVER)
        .encoder(FlyPacket::encode)
        .decoder(FlyPacket::decode)
        .consumerMainThread(FlyPacket::handle)
        .add();
```

**6.** 会读出错乱数据（readUtf 按字符串格式读原本 int 的字节，长度前缀都被误解），轻则数据乱码，重则抛异常断开连接。原则：**编码与解码是字节流的写读镜像，顺序、类型必须严格对称**——网络包本质上是"双方约定好格式的一串字节"。

## 实践项目二 · 参考答案

### 关键代码

**XpBankBlockEntity.java**

```java
package com.xpbank.xpbank.blockentity;

import net.minecraft.core.BlockPos;
import net.minecraft.nbt.CompoundTag;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.state.BlockState;

public class XpBankBlockEntity extends BlockEntity {

    private int storedXp = 0;

    public XpBankBlockEntity(BlockPos pos, BlockState state) {
        super(ModBlockEntities.XP_BANK_BE.get(), pos, state);
    }

    public int deposit(int amount) {
        storedXp += amount;
        setChanged();
        return storedXp;
    }

    public int withdrawAll() {
        int amount = storedXp;
        storedXp = 0;
        setChanged();
        return amount;
    }

    public int getStoredXp() {
        return storedXp;
    }

    @Override
    protected void saveAdditional(CompoundTag tag) {
        super.saveAdditional(tag);
        tag.putInt("storedXp", storedXp);
    }

    @Override
    public void load(CompoundTag tag) {
        super.load(tag);
        storedXp = tag.getInt("storedXp");
    }
}
```

**XpBankBlock.java 的 use 方法**

```java
@Override
public InteractionResult use(BlockState state, Level level, BlockPos pos,
                             Player player, InteractionHand hand, BlockHitResult hit) {
    if (!level.isClientSide() && player instanceof ServerPlayer serverPlayer) {
        BlockEntity be = level.getBlockEntity(pos);
        if (be instanceof XpBankBlockEntity bank) {
            if (player.isShiftKeyDown()) {
                int amount = bank.withdrawAll();
                serverPlayer.giveExperiencePoints(amount);
                player.sendSystemMessage(Component.literal("取出 " + amount + " 点经验"));
            } else {
                int deposit = serverPlayer.totalExperience / 10;
                if (serverPlayer.totalExperience >= 10 && deposit > 0) {
                    serverPlayer.giveExperiencePoints(-deposit);
                    int balance = bank.deposit(deposit);
                    player.sendSystemMessage(Component.literal(
                            "已存入 " + deposit + " 点经验，当前余额 " + balance));
                } else {
                    player.sendSystemMessage(Component.literal("经验不足，至少需要 10 点"));
                }
            }
        }
    }
    return InteractionResult.SUCCESS;
}
```

其余文件（注册类、DataGen、mods.toml、语言文件）均为模块一二讲过的模板代码，替换 ID 为 `xpbank` 即可。

### 挑战任务提示

1. 在 use 的服务端分支中播放音效即可。
2. `ExperienceOrb.award((ServerLevel) event.getLevel(), Vec3.atCenterOf(event.getPos()), xp)`。
3. 思路：悬浮提示在客户端执行，但余额在服务端。可行方案：重写 BE 的 `getUpdateTag()`/`handleUpdateTag()` 让 Forge 自动把 NBT 同步给客户端（配合 `getUpdatePacket()`），客户端 tooltip 里从 `level.getBlockEntity(pos)` 读取。注意物品形态的悬浮提示拿不到世界中的 BE——所以更简单的方案是只对"世界中指向方块"做提示，或发包查询。本题重点是意识到"两端数据隔离"这一架构约束。

### 常见扣分点自查

- 改数据是否在服务端分支？
- BE 字段修改后是否 `setChanged()`？
- BE 类型是否注册并在主类挂接？
- Tooltip 事件类是否限定 `Dist.CLIENT`？
- mods.toml 的 modId、包名、assets 文件夹名是否统一为 `xpbank`？
