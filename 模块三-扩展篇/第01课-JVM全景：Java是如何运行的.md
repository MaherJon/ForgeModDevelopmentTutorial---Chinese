## 1.1 一段代码的奇幻漂流

你在 IDEA 里写下 `System.out.println("hello")`，到屏幕上出现文字，中间发生了什么？

```
Hello.java (源代码)
    │
    │  javac 编译
    ▼
Hello.class (字节码)          ← 不是机器码！是一种"中间语言"
    │
    │  JVM 加载并执行
    ▼
JVM 把字节码翻译成本机机器码  ← Windows 翻译成 x86 指令，Mac M 系列翻译成 ARM 指令
    │
    ▼
CPU 执行
```

**关键洞察**：Java 编译器（javac）不直接生成 CPU 能懂的机器码，而是生成**字节码（bytecode）**——一种专为"Java 虚拟机"这台虚拟计算机设计的指令。真正运行时，由 JVM 负责把字节码翻译给真实的 CPU。

> 💡 **类比**：字节码像"世界语"。你写的文章先被翻译成世界语（字节码），到了任何国家，当地的翻译官（该国的 JVM）再把世界语翻成本国语言（机器码）。你只需写一次，全世界的翻译官都能接手。

这就是 Java 口号 **"Write Once, Run Anywhere"（一次编写，到处运行）** 的原理——你的模组 jar 在 Windows、Mac、Linux 上都能跑，因为各地都有对应的 JVM。

## 1.2 JDK、JRE、JVM 三者关系

这三个缩写新手必混，一张图说清楚：

```
┌─────────────── JDK（Java 开发工具包）───────────────┐
│  编译器 javac、调试工具、打包工具……  +  下面全部      │
│  ┌──────────── JRE（Java 运行时环境）────────────┐   │
│  │  Java 标准类库（String、List 这些） + 下面     │   │
│  │  ┌──────────── JVM（Java 虚拟机）──────────┐  │   │
│  │  │  真正执行字节码的"虚拟计算机"            │  │   │
│  │  └──────────────────────────────────────────┘  │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

- **JVM**：执行字节码的发动机；
- **JRE** = JVM + 标准类库（运行 Java 程序的最小环境）；
- **JDK** = JRE + 开发工具（javac 等）。

你第 01 课装的是 JDK——因为你要**开发**；普通玩家运行游戏只需要 JRE 级别的能力（启动器会自带）。

## 1.3 JVM 执行字节码的两种方式

JVM 不是简单地把字节码"逐条翻译"，它很聪明，有两种执行引擎配合：

### 解释器（Interpreter）：即来即翻

程序刚启动时，字节码由解释器逐条翻译执行。优点：启动快，不用等；缺点：每条指令都要翻译，慢。

### JIT 编译器（Just-In-Time，即时编译）：热点代码直接编译成机器码

JVM 会监控哪些代码被**频繁执行**（"热点代码"，比如游戏主循环）。一旦发现热点，JIT 就把这段字节码**整体编译成本机机器码**缓存起来，以后直接跑机器码，速度接近 C++。

```
启动初期：解释执行（慢但立刻能跑）
    │
运行中：JVM 发现"这段代码跑了上万次"
    ▼
JIT 编译成机器码（从此飞快）
```

> 💡 这就解释了为什么 Minecraft **刚进入世界时有点卡，玩一会儿就流畅了**——JIT 正在热身。也解释了性能测试不能只看启动头几秒。

## 1.4 这一切和 Minecraft / Forge 有什么关系？

回到我们的领域，看看你双击 runClient 后发生了什么：

```
runClient 任务
    │
    ▼
启动一个 JVM 进程（就是 java 程序），指定一大堆参数
    │
    ▼
JVM 加载 Minecraft 主类 → 游戏初始化
    │
    ▼
Forge 在启动早期介入，扫描所有 jar 里的 @Mod 注解（反射！）
    │
    ▼
类加载器把你的模组类加载进 JVM → new 出模组对象 → 注册 → 进入主界面
    │
    ▼
游戏主循环每秒跑 20 次 tick（JVM 里 JIT 逐渐优化这些热点代码）
```

你之前学的每个概念都能在这张图里找到位置：

- `javac` 编译：Gradle 的 build 任务帮你调用了它；
- `@Mod` 扫描：靠 JVM 的反射能力（模块二第 04 课）；
- 类怎么进 JVM：下一课的**类加载机制**；
- 游戏为什么卡顿：第 03 课的**垃圾回收**、第 05 课的**调优**。

## 1.5 本课小结

- Java 源文件 → 编译成**字节码**（.class）→ JVM 把字节码翻译成本机机器码执行。
- JVM 是跨平台的秘密：字节码统一，各平台的 JVM 各自翻译。
- JDK = JRE + 开发工具；JRE = JVM + 标准类库。
- JVM 双引擎：解释器负责快速启动，JIT 负责把热点代码编译成机器码提速——所以游戏会"越玩越流畅"。
- 启动游戏 = 启动一个 JVM 进程；你的模组类是被类加载器加载进 JVM 的。
